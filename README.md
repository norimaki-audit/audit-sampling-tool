# 監査サンプリング設計ツール

監査リスクの評価からサンプル数の算定、誤謬評価、監査調書の出力までをブラウザ上で支援する、IC STUDIOの教育型実務ツールです。

中心となる問いは、次の2つです。

- なぜ、そのサンプル件数なのか
- AIで全件を分析できるなら、サンプリングは必要なのか

AIやデータ分析は、母集団全体へ同じルールを適用し、例外候補を抽出する領域を広げます。一方、証憑の真正性、契約条件、承認の実態、取引の経済的実態、会計上の見積りなど、人による確認と判断が必要な領域は残ります。

このツールでは、全件分析、特定項目抽出、統計的・非統計的サンプリング、人による個別判断をどう組み合わせるかを整理し、入力条件に基づくサンプル件数の根拠と限界を確認できます。

[公開ページを開く](https://norimaki-audit.github.io/audit-sampling-tool/)

## 主な機能

- 計算タブ・「統計のきほん」タブ・理論編タブ・「AIとサンプリング」タブの4構成（計算画面には実数を代入した式を1行だけ表示）
- ①対象 → ②リスク評価 → ③特定項目控除 → ④サンプル数算定 → ⑤誤謬評価 → ⑥調書出力 の直線導線
- 監査リスクモデル（AR・IR・CR）の計算と、クリップ発動時の明示
- 統制テストのサンプル数設計と上限逸脱率評価（正確二項）
- BS・PL共通の金額単位サンプリング（MUS/PPS）
- PPS誤謬評価（過大計上・過小計上を別々に算定）
- エンジンから動的生成するサンプル数早見表
- 算式・算定根拠・警告を含む監査調書の出力
- デスクトップ・モバイル対応

## 使い方

1. [公開ページ](https://norimaki-audit.github.io/audit-sampling-tool/)を開くか、リポジトリをダウンロードして`index.html`をブラウザで開きます。
2. ①で対象とテストの種類（統制テスト／BS／PL）を選びます。
3. ②でAR・IR・CRと過信リスクROOを設定します。RIAは実証手続へ、ROOは統制テストへ流れます。
4. ③で特定項目を控除し、残余母集団を確定します（統制テストでは非表示）。
5. ④で必要サンプル数を確認します。式は実数を代入した形で1行表示されます。
6. ⑤で発見された逸脱・誤謬を入力し、上限逸脱率または推定誤謬上限で評価します。
7. ⑥で調書をコピーまたはダウンロードします。

ビルドやインストールは不要です。

## 計算前提

原理は2つだけです。統制テストは**属性サンプリング（正確二項）**、BS・PLは**金額単位サンプリング（ポアソン）**に統一しています。

### リスクモデル

```
DR  = AR ÷ (IR × CR)
RIA = clamp(DR, 1%, 20%)   実証手続の受入リスク
ROO = 別入力（5% / 10%）   統制テストの過信リスク
```

ROOは発見リスクから導出せず、統制に依拠する程度に応じた独立パラメータとして選択します。RIAのクリップが発動した場合は、元の値とあわせて画面と調書に明示します。

### 統制テスト（属性サンプリング）

- サンプル数は `n = min{ n : P(X ≤ x | n, TDR) ≤ ROO }`
- ROO=10%の表は既存の慣行値（5%:45/77/116、7%:32/55/77、9%:25/42/58）を維持
- ROO=5%の表は正確二項から導出（5%:59/93/124、7%:42/66/88、9%:32/51/68）
- 上限逸脱率は正確二項（Clopper–Pearson）片側上限 `ULD = BetaInv(1 − ROO, x + 1, n − x)`
- 判定は `ULD ≤ 許容逸脱率` のみで決まり、「逸脱0件なら無条件で有効」という先行分岐は持ちません
- 母集団250件未満の頻度別ルール（週次5件、月次2〜3件、四半期1件、年次1件）は実務慣行として維持しますが、**統計的サンプリングではない旨**を算定根拠に明記します

ROO=10%の表は統計的最小値ではなく慣行値で、逸脱2件の一部（5%→116、7%→77）は正確二項の最小値（105、75）より保守的です。いずれも上限逸脱率は許容逸脱率以下であり、統計的に妥当です。

### BS・PL共通（金額単位サンプリング）

```
CF = −ln(RIA)
n  = BV × CF ÷ (TM − EM × EF)      EF（拡大係数）= 1.6
SI = (TM − EM × EF) ÷ CF
```

- 期待誤謬EMは**分母からのみ**控除します（分子に `(1 + EM/TM)` を掛けません）
- サンプリング間隔は `BV ÷ n` ではなく直接算出し、丸め誤差を間隔へ伝播させません
- カバレッジ率は `(SI以上の高額項目の合計額 + 通常サンプルの抽出額) ÷ BV`。高額項目が未入力の場合は「算定不能」と表示します
- 丸めは最後に一度だけ行います

PL項目は共通式のあとに、監査要点（網羅性 ×1.5）、手法（階層化 ×0.85）、最低件数フロア（低30／中60／高90件）、絶対上限500件を適用します。フロアは上限より優先し、母集団が小さくフロアを満たせない場合は全件検証を検討する旨を警告します。リスク区分はRIAから導出します（RIA≥15%→低、5%≤RIA<15%→中、RIA<5%→高）。

### PPS誤謬評価

```
基本精度       = CF(0, RIA) × SI
汚染率 taint   = 誤謬額 ÷ 個別項目の簿価
推定誤謬       = taint × SI（簿価 ≥ SI なら誤謬額の実額）
増分許容誤謬   = Σ (CF(i) − CF(i−1) − 1) × 推定誤謬_i
                 ※ 対象は簿価 < SI の項目のみ。taint降順
UML            = 基本精度 + Σ推定誤謬 + 増分許容誤謬
```

- 誤謬件数に上限はありません。信頼係数はRIAからポアソン分位として動的に決定します（RIA=10%では従来のハードコード値2.31/3.89/5.33…を再現します）
- 簿価が SI 以上の項目は必ず抽出されるためサンプリングリスクがなく、増分許容誤謬の対象外です（研究文書第1号 6-7）。推定誤謬額には実額で算入します
- 過大計上と過小計上を別々に集計し、それぞれのUMLを表示します
- 誤謬件数が10件を超える場合は、サンプリングの前提が崩れている旨を警告します
- サンプリング間隔は評価画面で直接入力・上書きできます（`BV ÷ n` で再計算しません）

### 早見表

早見表は静的HTMLではなく、計算画面と同一の関数から生成しています。行の索引はBS・PLとも**母集団簿価 ÷ 許容誤謬**に統一しています。

## 表示される説明について

計算画面に表示される「実数を代入した式（1行）」「算定根拠」「警告」は、すべて`engine.js`が入力値と固定ルールからブラウザ内で生成しています。生成AIや外部AI APIは使用しておらず、AIによる診断結果ではありません。

- **算式**: `formula.substituted`。例 `n = 500,000,000 × 2.30 ÷ (15,000,000 − 1,500,000×1.6) = 91件`
- **算定根拠**: `basis`。どの分布・どの前提を使ったか、統計的サンプリングか実務慣行かを明記します
- **警告**: `warnings`。リスククリップの発動、フロア未達、過小計上の検出、誤謬件数の過多などを通知します

理論的な背景と各式の導出は「理論編」タブにまとめています。計算画面には式を1行だけ表示し、解説は混在させていません。

## 全件分析について

全件分析は、母集団全体へ処理を実行したという意味では全件ですが、監査上必要な判断をすべて完了したことを意味しません。

次の点は別途確認が必要です。

- 元データと抽出結果の完全性・正確性
- 判定ルール、プログラム、分析ロジックの妥当性
- 検出された例外項目の評価
- 証憑の真正性、契約条件、取引の経済的実態
- 経営者の見積りや判断の合理性

サンプリングは単純になくなるのではなく、全件分析や特定項目抽出を行った後の残余母集団など、適用される場所が変わる可能性があります。

## データの取扱い

このツールの計算処理はブラウザ内で完結します。

- 入力した会社名、勘定科目、金額、サンプリング結果をサーバーへ送信する処理はありません。
- `fetch`、`XMLHttpRequest`、WebSocket、アクセス解析、テレメトリーは使用していません。
- `localStorage`へ保存する項目はありません。
- 入力した監査データはリポジトリへ自動保存されません。
- コピーや調書出力を実行した場合、データは利用者のクリップボードまたは端末上のファイルとして扱われます。

## 注意事項

本ツールの結果は、入力条件に基づく統計的な目安です。監査基準への準拠、内部統制の有効性、監査判断の妥当性を保証するものではありません。

実際の判断では、監査目的、母集団の性質、監査方針、逸脱内容、所属法人の監査マニュアル等を確認し、監査人の職業的専門家としての判断を行ってください。

## 統計のきほん タブ

統計を学んだことがない方向けに、理論編の**一歩手前**を6章で解説しています。

1. **なぜ一部を見ただけで全体のことが言えるのか** — サンプリングは当てにいく手続ではなく可能性を絞り込む手続であること。無作為抽出が条件であること
2. **分布とは何か** — 起こりうる結果と起こりやすさの一覧。`P(X ≤ 2 | n=25, p=9%)` の読み方
3. **二項分布をゼロから** — `nCx × p^x × (1−p)^(n−x)` を3つの部品に分解。`0.91^23 = 11.4% / 0.91^24 = 10.4% / 0.91^25 = 9.5%` から**25件が出てくる過程**
4. **ポアソン分布をゼロから** — 二項分布がポアソンに近づく様子を数値表で。`P(X=0) = e^(−λ)` が出発点であること
5. **「90%の信頼度」と対数** — 信頼度の正しい意味（真の値が範囲に入る確率**ではない**）。`ln` は「e を何乗したか」を返すだけであること
6. **ここから先へ** — 理論編・AIタブへの導線

掲載している数値はすべて `engine.js` で機械的に検算しています。

## 理論編タブ

統計を専攻していない監査人向けに、次の順で解説しています。変更履歴ではなく理解に重点を置いています。

1. **記号の読み方** — 17語の略語をフルスペル・日本語・実務での意味で一覧化。「①どこまで間違えてよいか → ②合格ラインをどこに引くか → ③何をどれだけ見るか → ④結果を母集団に戻す」の4層に整理し、混同しやすい RIA/ROO、TM/EM、ULD/UML を対比
2. **なぜ監査リスクを数値で置くのか** — 低・中・高は順序しか持たず掛け算・割り算に載らないこと。数値化は判断を精密にする作業ではなく計算につなぐ翻訳であること。`CF = −ln(RIA)` の性質から、RIA を半分にすると件数は出発点によらず `(BV÷TM)×0.693` だけ増えること
3. **統制テスト：なぜ二項分布か** — 1件ごとが二値であること。逸脱率0付近・小標本で正規近似が壊れる理由。上限逸脱率は「どこまで悪い可能性を否定できたか」の境界であること。正確二項 9.94% とポアソン近似 10.54% で結論が反転する実例
4. **実証手続：なぜポアソン分布か** — 1円を抽出単位とみなすと単位数が膨大・誤謬確率が微小になり、二項分布のポアソン極限が使えること。統制テストと分布が違うのは母集団の捉え方が違うためで矛盾ではないこと
5. **式の意味** — `e^(−λ) = RIA` を解いて `CF(0) = −ln(RIA)` が出る導出。`基本精度 = CF(0) × SI = TM − EM×EF` という恒等式。拡大係数が受入リスクごとの表で与えられる値であり、固定値1.6は5%に対応すること
6. **UML の組み立て** — 3つの積み木（基本精度・Σ推定誤謬・増分許容誤謬）。増分係数が逓減すること。簿価≥SI の高額項目に上乗せが発生しない理由。過大計上と過小計上を相殺しない理由
7. **サンプル数早見表** — エンジンから動的生成
8. **サンプリング実施前の留意点**

### 設計上の注意として計算画面が警告する事項

- **期待誤謬を0にすると基本精度が許容誤謬と一致する** — `基本精度 = TM − EM×EF` なので EM=0 では基本精度がちょうど TM になり、誤謬を1円でも発見すると必ず「受入不可」になります
- **拡大係数 1.6 は受入リスク5%に対応する値** — 標準表は `1%:1.90 / 5%:1.60 / 10%:1.50 / 15%:1.40 / 20%:1.30 / 25%:1.25` です。本ツールは仕様により 1.6 に固定しているため、RIA が 5% から離れるほどずれます。RIA<5% では取り置きが不足する旨、RIA>5% では保守側である旨をそれぞれ警告します
- **統制リスクを 1.00 未満にするには運用評価手続が前提** — 監査基準報告書315 第33項により、統制テストを実施しない場合は重要な虚偽表示リスクと固有リスクが同じ評価になります
- **母集団件数10%の上限が効くと信頼水準が達成されない** — 上限で切り詰めた場合、入力した RIA に対応する信頼水準は満たされない旨を警告します
- **標準サンプル数表は正確二項の最小値と一致しないことがある** — 慣行表を引いた場合、算式表示は最小化の式ではなく `標準表[…] = 116件（正確二項の最小値 105件を上回る保守側の慣行値）` と表示します

### 初心者レビューで発見・修正した欠陥

4つの読者像（監査法人1年目／内部統制部門／統計未履修の5年目／経理からの転職者）で実際に画面をたどらせ、詰まる箇所を洗い出しました。実害のあった3件を修正しています。

- **BS で必要サンプル数が母集団件数を超えても全件化せず、警告も出なかった** — 全件化の処理が PL のブロック内にありました。BS・PL 共通に移し、「精査として設計してください」の案内を追加
- **誤謬を1件も入力していない段階で「受入可能（条件付き）」が緑色で表示された** — 期待誤謬0の設計では `基本精度 = 許容誤謬` となり `UML ≦ TM` が成立するためです。手続未実施のまま調書に貼られる事故を防ぐため、明細が空のときは「未評価」とし、「誤謬は発見されなかった」のチェックを入れるまで評価しないようにしました
- **網羅性を選んでも警告がなかった** — 金額単位サンプリングは計上済み母集団から金額比例で抽出するため、計上漏れの検証には構造的に向きません。その旨と代替手続の方向性を警告として追加

あわせて、値の出どころが分からない入力欄（許容誤謬・固有リスク・統制リスク）に「監査計画から転記する値です」と明記し、③に作業手順、⑤に簿価と監査後価値の定義を追加しました。過信リスク ROO は統制テスト以外では非表示にしています。

### 統計的な立場

本ツールは**頻度論（frequentist）**に基づいており、ベイズ統計は用いていません。事前分布・事後分布の概念は実装に存在しません。

- 上限逸脱率は、二項分布のCDFを逸脱率について逆に解いたもの（Clopper–Pearson）です。頻度論の検定を反転させる手続きであり、事前の信念を更新する操作ではありません
- 「統計のきほん」タブの信頼度の説明も頻度論の解釈で統一しています（「真の逸脱率は既に決まっている一つの数であり、それに確率は割り当てない」）
- `ULD = BetaInv(1 − ROO, x + 1, n − x)` とベータ分布が現れますが、これは二項分布の逆解きがベータ分位点と一致するためです。数値としては特定の事前分布を置いたベイズ事後分位点と一致しますが、導出は頻度論です

なお上表で参照している高田論文は、タイトルのとおりベイズの定理を扱った論文です。ただし**本ツールが照合したのは式(1)・式(4)・第1表というリスクモデルの部分のみ**で、同論文第III章の「ベイズの定理による固有リスクの改訂」は実装していません。固有リスク IR は利用者が直接入力する値として扱っています。

これは現行の監査基準・実施基準が二項分布とポアソン分布を前提としていること（「統計上の二項分布を前提とすると、90%の信頼度を得るには…少なくとも25件」）に合わせた選択です。

### 修正した不適合

**増分許容誤謬に簿価 ≥ SI の項目を含めていました。** 簿価が抽出間隔以上の項目は必ず抽出されるためサンプリングリスクが存在せず、研究文書第1号 6-7 により増分の対象外です。修正前は設問6-8 の設例で増分許容誤謬が 9,200千円（文献 8,760千円）となっていました。

4,000ケースの無作為検証では、修正前の実装が**過小になったケースは0件**で、常に過大（保守側）でした。監査意見を誤らせる方向ではありませんでしたが、不要な「受入不可」を生むため修正しています。

### 用語

日本の監査基準は Detection Risk の訳語として**「発見リスク」**を用います（平成14年改訂監査基準意見書、監査基準報告書200 第12項(15)）。v3.0 では「検出リスク」から全面的に改めました。

## AIとサンプリング タブ

「AIで全件を分析できるなら、サンプリングは要らなくなるのか」という問いを6章で整理しています。

1. **基準はサンプリングをどう位置づけているか** — 抽出方法を定めているのは監査基準報告書500「監査証拠」A52項で、精査（100%の検討）・特定項目抽出による試査・監査サンプリングによる試査を並列に置いています。監査基準報告書530 は第1項で「監査サンプリングを利用する場合に適用する」と述べており、サンプリングを義務づける基準ではないこと
2. **「全件処理した」と「全件確かめた」は違う** — データの完全性・正確性、判定ロジックの妥当性、例外項目の評価、データに写らない事実（証憑の真正性・経済的実態・見積り）
3. **大手監査法人のツールは何をしていると言っているか** — マーケティング文言と監査手続上の位置づけの読み分け
4. **サンプリングはどこへ移るのか** — 母集団の層別と残余母集団。監査基準報告書500 A55項「特定項目抽出による試査は…母集団の残余部分に関する監査証拠を提供しない」。本ツールの③特定項目控除に対応
5. **新しく生まれるリスク** — 出力への過信、ブラックボックス化、誤検知への埋没、ツール自体の信頼性。FRC(2021)の outliers/exceptions の区別と不適切なパラメータ調整、IAASB(2025)に記録された規制当局の「見てしまったものを見なかったことにはできない」という指摘
6. **実務でどう整理するか** — 計画時の6つの検討順序
7. **参照した資料** — 原文を確認した基準・監査法人公表資料・学術研究の一覧

主要な出典は IAASB の技術関連FAQ（2020年11月・2023年2月）、IAASB Technology Position（2024年9月）、PCAOB Release No. 2024-007（2025年12月15日以後開始事業年度から適用）、FRC のADA例外対応ガイダンス（2021年8月）、および Huang et al.(2022) / No et al.(2019) / Eilifsen et al.(2020) / Barr-Pulliam et al.(2022) です。

## ファイル構成

- `index.html`: 画面構造（計算・統計のきほん・理論編・AIとサンプリングの4タブ）
- `engine.js`: 計算エンジン。純関数のみでDOMを一切参照しない
