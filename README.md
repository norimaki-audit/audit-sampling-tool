# 監査サンプリング設計ツール

統制テストと金額単位サンプリング（MUS / PPS）の設計・誤謬評価を、ブラウザ上で補助する個人開発ツールです。

- 公開ページ: https://norimaki-audit.github.io/audit-sampling-tool/
- リポジトリ: https://github.com/norimaki-audit/audit-sampling-tool
- ビルド不要、外部ランタイム依存なし
- 入力値と計算はブラウザ内で処理

## できること

1. 監査対象とテスト種別の整理
2. 監査リスクモデル `DR = AR / (IR x CR)` の確認
3. 統制テストの属性サンプリング設計と上限逸脱率（ULD）の算定
4. BS・PL項目の金額単位サンプリング設計
5. MUSによる過大計上の推定誤謬上限（UML）の算定
6. 算式、根拠、警告を含む検討用テキストの出力
7. 統計の基礎、計算理論、抽出方法、AIとサンプリングの解説

## 最初に確認してください

このツールは数値計算を補助しますが、監査結論を自動で決めません。

- `DR`、`RIA`、`ROO`は目的の異なるリスクです。`RIA`と`ROO`は`DR`から自動変換せず、監査計画と所属法人等のメソドロジーに従って設定します。
- 統計的な上限が許容値以下でも、母集団の適合性・完全性、抽出方法、誤謬や逸脱の性質・原因、定性的影響、他の監査証拠を評価する必要があります。
- 非統計的サンプリングのULDは参考値です。その数値だけで統計的な結論は導けません。
- MUSは計上済み簿価から金額比例で抽出するため、未計上項目や簿価0の項目の完全性検証には適しません。過小計上は既知額として別表示し、統計的に投影しません。
- 出力テキストだけでは、十分かつ適切な監査証拠又は正式な監査調書になりません。

## 計算の概要

### 統制テスト

統計的サンプリングでは、過信リスク`ROO`、許容逸脱率`TDR`、計画上の予想逸脱件数`x`から必要件数を求めます。

```text
n = min { n : P(X <= x | n, TDR) <= ROO }
ULD = BetaInv(1 - ROO, observed deviations + 1, n - observed deviations)
```

`ROO=10%`かつ標準的なTDRでは慣行表を使用し、それ以外は正確二項から導出します。小規模・低頻度の統制でも自動的に非統計へ切り替えず、利用者が統計的／非統計的を明示します。

### 金額単位サンプリング

```text
CF = -ln(RIA)
EF = RIAに対応する拡大係数
SI = (TM - EM x EF) / CF
n  = BV x CF / (TM - EM x EF)
```

主な記号:

| 記号 | 意味 |
|---|---|
| `BV` | サンプリング対象の母集団簿価 |
| `TM` | 当該サンプリング手続に設定した許容誤謬 |
| `EM` | 期待誤謬 |
| `RIA` | 誤って母集団を受け入れるリスク |
| `CF` | 信頼係数 |
| `EF` | RIAに対応する拡大係数 |
| `SI` | サンプリング間隔 |

算定される`n`は選択ポイント数です。同じ高額項目が複数ポイントにヒットする場合があるため、ユニークな証憑・項目数と一致しないことがあります。

PLだから一律に件数を増減する、網羅性だから1.5倍にする、層化だから15%減らす、最低件数・10%上限・500件上限を置く、といった基準上の根拠が明確でない自動補正は行いません。層化や法人固有のルールを採用する場合は、各層と判断根拠を別途設計・文書化してください。

### MUSの誤謬評価

過大計上について、基本精度、推定誤謬、増分許容誤謬からUMLを算定します。

```text
UML = 基本精度 + 推定誤謬 + 増分許容誤謬
```

- 簿価が`SI`未満: 汚染率 `誤謬額 / 個別項目の簿価` を`SI`へ投影
- 簿価が`SI`以上: 誤謬実額を使用し、増分許容誤謬のランク付け対象外
- 過小計上: 既知額のみ表示し、MUSでは投影しない

## 基準・公表資料との照合

2026年8月時点の公開資料を参照して、次の考え方を実装しています。

- [監査基準報告書530「監査サンプリング」](https://jicpa.or.jp/specialized_field/2-24-530-2-20230810.pdf): 監査目的と母集団特性の考慮、サンプリングリスクを許容可能な低い水準へ抑える十分なサンプル数、母集団の全抽出単位に抽出機会を与えること、結果の評価
- [監査基準報告書530 研究文書第1号](https://jicpa.or.jp/specialized_field/2-24-530k_1-2-20221013.pdf): 属性サンプリング及び金額単位サンプリングの実務上の計算例
- [監査基準報告書500「監査証拠」](https://jicpa.or.jp/specialized_field/2-24-500-3-20230112.pdf): 十分かつ適切な監査証拠、監査人が作成した情報の正確性・完全性等
- [監査基準報告書450「監査の過程で識別した虚偽表示の評価」](https://jicpa.or.jp/specialized_field/2-24-450-2-20221013.pdf): 識別した虚偽表示の集計、性質・原因・影響及び未修正虚偽表示の評価

本ツールはこれらの基準本文を置き換えるものではありません。改正の有無と最新版は利用時に確認してください。

## 情報セキュリティ

通常の利用ではサーバー送信処理やアクセス解析を実装しておらず、計算はブラウザ内で完結します。ただし、公開Webページであること自体が機密情報の入力を正当化するものではありません。

- 実在するクライアント名、個人名、取引先名、証憑番号等は、必要がなければ入力しないでください。
- 実データを扱う場合は、所属組織の守秘義務、情報セキュリティ、外部サービス利用及びデータ保存の方針に従ってください。

- リポジトリには実在クライアントのデータをコミットしないでください。テストデータは架空・匿名化した値だけを使用します。

## ローカルで使う

静的ファイルだけで動作します。`index.html`をブラウザで開くか、任意の静的サーバーで配信してください。

```bash
npx serve .
```

## テスト

Node.js 20以降を推奨します。

```bash
npm test
```

テストは正確二項、ポアソン信頼係数、リスクパラメータの独立性、RIA対応EF、MUS投影、過小計上の非投影、非統計的サンプリングの制約等を検証します。
