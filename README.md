# 監査サンプリング設計ツール

監査リスクの評価からサンプル数の算定、誤謬評価、監査調書の出力までをブラウザ上で支援する、IC STUDIOの教育型実務ツールです。

中心となる問いは、次の2つです。

- なぜ、そのサンプル件数なのか
- AIで全件を分析できるなら、サンプリングは必要なのか

AIやデータ分析は、母集団全体へ同じルールを適用し、例外候補を抽出する領域を広げます。一方、証憑の真正性、契約条件、承認の実態、取引の経済的実態、会計上の見積りなど、人による確認と判断が必要な領域は残ります。

このツールでは、全件分析、特定項目抽出、統計的・非統計的サンプリング、人による個別判断をどう組み合わせるかを整理し、入力条件に基づくサンプル件数の根拠と限界を確認できます。

[公開ページを開く](https://norimaki-audit.github.io/audit-sampling-tool/)

## 主な機能

- 監査アプローチの比較（全件分析、特定項目抽出、統計的・非統計的サンプリング、組合せ）
- AI・データ分析で全件分析しやすいかを考えるチェック
- AI時代の監査手続フローと全件分析の限界整理
- 監査リスクモデル（AR・IR・CR）の計算
- 統制テストのサンプル数設計
- 入力条件から生成する「なぜこの件数になったのか」の説明
- 現在値に連動する「条件 → 基準表 → 母集団上限 → 必要件数」の算定順序
- 入力条件変更前後の比較と感度分析
- BS項目のPPS/MUSサンプリング
- PL項目の実証サンプリング
- 非統計的サンプリングの判断支援
- 統制逸脱・実証手続の誤謬評価
- サンプル数早見表
- 計算結果のコピーと監査調書出力
- デスクトップ・モバイル対応

## 使い方

1. [公開ページ](https://norimaki-audit.github.io/audit-sampling-tool/)を開くか、リポジトリをダウンロードして`index.html`をブラウザで開きます。
2. 必要に応じて「監査アプローチ」で母集団のテスト方法を整理します。
3. 監査対象情報、リスク評価、母集団情報を入力します。
4. 必要サンプル数と「なぜこの件数になったのか」を確認します。
5. 詳細表示では、条件変更前後の比較、感度分析、AI時代の監査手続フローを確認できます。
6. 必要に応じて結果をコピーするか、監査調書を出力します。

ビルドやインストールは不要です。

## 計算前提

### 統制テスト

既存版の基準表と頻度別ルールを維持しています。

- 母集団250件以上または日次・随時統制は、許容逸脱率と予想逸脱件数に対応する基準表を使用
- 基準表は許容逸脱率5%、7%、9%と予想逸脱0件、1件、2件の組合せ
- 週次、月次、四半期、年次統制は既存の頻度別基準を使用
- 基準件数が母集団件数を上回る場合は、母集団件数を上限として全件確認
- 件数計算で端数が生じる場合は切り上げ

統制テストの基準表は90%信頼度を前提としています。画面上の監査リスクモデルの信頼度を変更しても、この基準表自体を独自に補間しません。

### BS項目

既存版のPPS/MUS計算を維持しています。受入リスク、帳簿価額、許容誤謬、期待誤謬から信頼係数と修正信頼係数を求め、サンプル数を切り上げます。

### PL項目

既存版の計算を維持しています。母集団取引件数、リスク評価、信頼度、許容誤謬率、重点アサーション、階層化の有無を用いて調整し、母集団の10%または500件を上限とします。

### 感度分析

- 母集団件数、許容逸脱率、予想逸脱件数は、統制テストの既存基準を用いて比較します。
- 信頼水準は、PL実証手続の既存調整ロジックを用いて比較します。
- グラフは入力条件の影響を理解するための比較であり、監査判断を確定するものではありません。

## 表示される説明について

「なぜこの件数になったのか」、入力条件の増減要因、全件分析チェックの結果は、入力値と固定ルールからブラウザ内で生成しています。生成AIや外部AI APIは使用しておらず、AIによる診断結果ではありません。

説明は次の順序を基本としています。

1. 監査実務の具体例
2. 数字が意味すること
3. 正式な統計用語
4. 必要な場合のみ計算ロジック

## 全件分析について

全件分析は、母集団全体へ処理を実行したという意味では全件ですが、監査上必要な判断をすべて完了したことを意味しません。

次の点は別途確認が必要です。

- 元データと抽出結果の完全性・正確性
- 判定ルール、プログラム、分析ロジックの妥当性
- 検出された例外項目の評価
- 証憑の真正性、契約条件、取引の経済的実態
- 経営者の見積りや判断の合理性

サンプリングは単純になくなるのではなく、全件分析や特定項目抽出を行った後の残余母集団など、適用される場所が変わる可能性があります。

## テスト

統制テストとPL実証手続の代表的な既存結果を回帰テストできます。

```powershell
node tests/calculation-regression.test.cjs
```

テスト対象の純粋な計算関数は`calculations.js`にあります。既存の画面上の計算結果と一致することを確認してから、教育UIと感度分析で参照しています。

## note記事との連動

解説記事の公開後、`education.js`の`NOTE_ARTICLE_URL`へURLを設定すると、画面内の「解説記事を読む」ボタンを有効化できます。

想定タイトル:

> AIは監査サンプリングをなくすのか？――「なぜ60件？」を統計学から考える

## データの取扱い

このツールの計算処理はブラウザ内で完結します。

- 入力した会社名、勘定科目、金額、サンプリング結果をサーバーへ送信する処理はありません。
- `fetch`、`XMLHttpRequest`、WebSocket、アクセス解析、テレメトリーは使用していません。
- `localStorage`に保存するのは表示倍率（`auditToolZoom`）だけです。
- 入力した監査データはリポジトリへ自動保存されません。
- コピーや調書出力を実行した場合、データは利用者のクリップボードまたは端末上のファイルとして扱われます。

### 外部通信

画面表示のため、次の公開CDNからフォントとアイコンを読み込みます。

- Google Fonts: `fonts.googleapis.com`、`fonts.gstatic.com`
- Phosphor Icons: `unpkg.com`

入力フォームの値をCDNへ送る実装はありません。ただし、一般的なWebアクセスと同様にIPアドレスやUser-Agentなどの通信情報が伝わる可能性があります。完全なオフライン環境では、外部リソースを組織内でホストするか、システムフォントへ置き換えてください。

## 公開リポジトリとしての確認

2026年8月4日時点で、現在のファイルと到達可能なGit履歴を次の観点で確認しています。

- 実在するクライアント名やクライアントデータが含まれていないこと
- メールアドレス、電話番号、住所などの個人情報がファイル本文に含まれていないこと
- APIキー、アクセストークン、秘密鍵、パスワードが含まれていないこと
- Gitコミットの作者情報にGitHubのnoreplyアドレスを使用すること

公開リポジトリへ実際のクライアントデータ、出力した監査調書、証憑、Excel・CSV・PDFをコミットしないでください。

## 注意事項

本ツールの結果は、入力条件に基づく統計的な目安です。監査基準への準拠、内部統制の有効性、監査判断の妥当性を保証するものではありません。

実際の判断では、監査目的、母集団の性質、監査方針、逸脱内容、所属法人の監査マニュアル等を確認し、監査人の職業的専門家としての判断を行ってください。

## ファイル構成

- `index.html`: 既存アプリケーション本体
- `calculations.js`: 回帰テストと教育UIで参照する純粋な計算関数
- `calculation-integration.js`: 統制テストの計算結果を既存画面へ反映
- `education-ui.js`: 教育UIの画面構造
- `education.js`: 根拠説明、比較、チェック、感度分析
- `education-bindings.js`: 既存計算と教育UIの連動
- `compatibility-fixes.js`: 既存参考表と追加コントロールの表示整合
- `education.css`: 現行IC STUDIOデザインを継承した追加スタイル
- `compact-ui.js`: 入力カードの整理と現在値に連動する算定ロジック解説
- `compact-ui.css`: コンパクトUIと算定順序表示のレスポンシブスタイル
- `tests/calculation-regression.test.cjs`: 計算結果の回帰テスト
