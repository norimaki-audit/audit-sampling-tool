      01なぜ一部を見ただけで全体のことが言えるのか
      
              
        
              
          サンプリングにいちばん最初に感じる違和感は、おそらくこれだと思います。
          1万件のうち25件しか見ていないのに、どうして残りの9,975件について何か言えるのか。
        
              
        
              
          答えを先に言うと、「言える」のは限られた形だけです。
          25件を見てわかるのは「母集団の逸脱率はちょうど◯%です」ではありません。
          わかるのは「逸脱率が◯%より高いとは考えにくい」ということだけです。
          サンプリングは、当てにいく手続ではなく、可能性を絞り込む手続です。
        
              

        
              絞り込みが成り立つ条件
              
        
              
          この絞り込みが成り立つのは、抽出が無作為である場合に限られます。
          無作為とは「母集団のどの項目にも、抽出される機会が与えられている」ということです。
          くじ引きのように運任せにする、という意味ではありません。
        
              
        
              
          なぜ無作為でないと成り立たないのか
          たとえば、期末月の伝票だけ25件抜いたとします。全部問題ありませんでした。
          このとき言えるのは「期末月の伝票は問題が少なそうだ」までで、
          期首の伝票については何も言えません。抽出されない部分があると、
          その部分について結論を及ぼす根拠がなくなるのです。
          「手間のかかる取引を避けて抜く」「手元にある綴りから抜く」も、同じ理由で成り立ちません。
        
              
        
              
          監査基準もこの点を明確にしています。監査基準報告書500 A55項は、
          特定の項目だけを狙って抜き出す方法について
          「母集団の中から抽出されない母集団の残余部分に関する監査証拠を提供しない」と述べています。
          金額の大きいものだけを見るのは有効な手続ですが、
          それだけでは残りについて語れないということです。
        
              

        
              「代表している」とはどういうことか
              
        
              
          無作為に25件抜くと、その25件は母集団の縮図になりやすくなります。
          ただし「必ず縮図になる」わけではありません。たまたま良いところばかり引くこともあります。
          統計が扱うのは、まさにこの「たまたま外す可能性」です。
          これをサンプリングリスクと呼び、あらかじめ「何%までなら外してもよいか」を決めておきます。
          本ツールの ROO（過信リスク）や RIA（受入リスク）は、この「何%まで」にあたります。
        
              
        
              
          
              
            誤解
            
              サンプル数を増やせば、いつかは確実になる。
              
          
              
          
              
            正しくは
            
              全件を見ない限り、外す可能性はゼロになりません。増やせるのは確実性ではなく絞り込みの細かさです。だからこそ「どこまで絞れれば十分か」を先に決める必要があります。
              
          
              
        
              
      
              
    
              

    
              
      02分布とは何か
      
              
        
              
          「分布」という言葉が出てくると身構えてしまいますが、中身は単純です。
          起こりうる結果を全部並べて、それぞれの起こりやすさを書き添えた一覧表のことです。
        
              
        
              
          統制テストで25件を検証するとします。結果として起こりうるのは
          「逸脱0件」「1件」「2件」…「25件」の26通りです。
          この26通りそれぞれに「どのくらい起こりやすいか」を割り当てたものが分布です。
        
              

        
              実際に並べてみる
              
        
              
          仮に母集団の真の逸脱率が9%だったとして、25件抜いたときの結果を並べると次のようになります。
        
              
        
              
          
              
            
              逸脱0件1件2件3件4件
              
            
              
              9.5%23.4%27.8%21.1%11.5%
              
                          
          
              
        
              
        
              
          いちばん起こりやすいのは「2件」で27.8%です。「0件」も9.5%の見込みで起こります。
          真の逸脱率が9%もある母集団でも、25件抜いて1件も出ないことは十分にありうる——
          この事実が、後の話につながっていきます。
        
              

        
              知っておくと読みやすくなる2つの言葉
              
        
                
          
              • 確率変数 — 「やってみるまで決まらない数」のことです。
            上の例なら「25件中の逸脱件数」がこれにあたります。慣例で大文字の X と書きます。
                • 
          
              • 期待値 — 何度も繰り返したときの平均です。
            逸脱率9%で25件なら、期待値は 25 × 0.09 = 2.25件 です。
            ただし2.25件という結果が実際に出ることはありません。あくまで平均の話です。
                • 
        
              
        
              
          記号の読み方
          P(X = 2) は「X が 2 になる確率」と読みます。P は Probability（確率）の頭文字です。
          P(X ≤ 2) なら「X が 2 以下になる確率」、つまり0件・1件・2件のいずれかになる確率で、
          上の表の3つを足しておよそ61%です。
          | という縦棒が出てきたら「〜という条件のもとで」と読みます。
          P(X ≤ 2 | n=25, p=9%) は「25件抜いて、真の逸脱率が9%のとき、逸脱が2件以下になる確率」です。
        
              
      
              
    
              

    
              
      03二項分布をゼロから
      
              
        
              
          統制テストは、1件ずつ「承認印があるか・ないか」を見ていきます。
          結果が二択で、それを決まった回数くり返す。
          この形をそのまま数式にしたものが二項分布です。
        
              
        
              P(X = x) ＝ nCx × p^x × (1−p)^(n−x)

  n  … 見る件数
  p  … 1件が逸脱である確率（母集団の真の逸脱率）
  x  … 逸脱が何件出るか
              

        
              3つの部品に分けて読む
              
        
                
          
              • p^x — 逸脱が x 件続けて起きる確率です。
            逸脱率9%なら、2件とも逸脱である確率は 0.09 × 0.09。掛け算になります。
                • 
          
              • (1−p)^(n−x) — 残りが全部OKである確率です。
            25件中2件が逸脱なら、残り23件はすべてOK。0.91 を23回掛けます。
                • 
          
              • nCx — どの位置で逸脱が起きるかの組合せの数です。
            25件のうち2件が逸脱といっても、1番目と2番目かもしれませんし、5番目と20番目かもしれません。
            その通り数を数えたもので、25件から2件を選ぶ組合せは300通りあります。
                • 
        
              
        
              
          なぜ組合せを掛けるのか
          「特定の並び順で起きる確率」を求めたあと、
          「同じ件数になる並び方が何通りあるか」を掛け戻しているだけです。
          2件が逸脱になる道すじが300通りあるなら、そのどれでも「2件」という結果になります。
          だから300を掛けます。
        
              

        
              これで「25件」が出てきます
              
        
              
          統制テストのサンプル数は、この式から決まります。考え方はこうです。
        
              
        
              
          「もし母集団の逸脱率が許容できない水準（たとえば9%）だったとして、
          n件を抜いて逸脱が1件も出ない確率が10%以下になるなら、その n で十分」
        
              
        
              
          なぜかというと、逸脱0件という結果が出たとき、
          「実は9%も逸脱していたのに、たまたま見つからなかっただけ」という可能性が
          10%以下しか残らないからです。この10%が過信リスク ROO です。
        
              
        
              
          逸脱0件の確率は、上の式で x = 0 とすればよく、
          nC0 = 1、p^0 = 1 なので (1−p)^n、
          つまり 0.91 を n 回掛けた数になります。
        
              
        
              n = 23:  0.91 を23回掛ける = 11.4%   → 10%を超える
n = 24:  0.91 を24回掛ける = 10.4%   → まだ超える
n = 25:  0.91 を25回掛ける =  9.5%   → 10%以下になった ✓
              
        
              
          これが「25件」の中身です。
          内部統制の実施基準にある「統計上の二項分布を前提とすると、90%の信頼度を得るには
          少なくとも25件のサンプルが必要になる」という記述は、この計算を指しています。
          暗記する数字ではなく、電卓で確かめられる数字です。
        
              
        
              
          
              
            誤解
            
              25件という数が、母集団1万件でも10万件でも同じなのはおかしい。
              
          
              
          
              
            正しくは
            
              上の計算に母集団の件数は一度も出てきません。効いているのは「逸脱率」だけです。母集団が十分に大きければ、その大きさはほとんど影響しません。逆に母集団が小さい（250件未満など）ときはこの前提が崩れるため、本ツールでは頻度別のルールに切り替えています。
              
          
              
        
              
      
              
    
              

    
              
      04ポアソン分布をゼロから
      
              
        
              
          実証手続（BS・PL項目の金額のテスト）では、二項分布ではなくポアソン分布を使います。
          分けている理由は、母集団の数え方が変わるからです。
        
              
        
              
          金額単位サンプリングでは、5億円の売掛金を5億個の「1円」が並んでいると考えます。
          すると数え上げる単位の数が桁違いに増え、逆に1単位あたりが誤っている確率は極端に小さくなります。
        
              
        
              
          この「回数はとても多いが、1回あたりの確率はとても小さい」という状況を
          扱いやすくしたのがポアソン分布です。
        
              
        
              P(X = k) ＝ e^(−λ) × λ^k ÷ k!

  λ（ラムダ） … 平均して何回起きる見込みか
  k           … 実際に何回起きるか
              

        
              二項分布が近づいていく様子
              
        
              
          「平均2.30回起きる」という条件を保ったまま、件数 n を増やして確率 p を小さくしていくと、
          二項分布の答えがポアソン分布の答えに近づいていきます。
        
              
        
              
          
              
            
              件数 n1件あたりの確率 p「0回」の確率
              
            
              
              1023.03%7.3%
              
              
              1002.303%9.7%
              
              
              1,0000.2303%10.0%
              
              
              100,0000.0023%10.0%
              
              
              ポアソン—10.0%
              
                          
          
              
        
              
        
              
          5億という単位数は、この表のいちばん下と実質的に同じです。
          だから二項分布ではなくポアソン分布を使ってよいことになります。
          統制テストと分布が違うのは矛盾ではなく、母集団を件数で見るか金額で見るかの違いです。
        
              

        
              いちばん大事なのは「0回の確率」
              
        
              
          式で k = 0 とすると、λ^0 = 1、0! = 1 なので、次のように簡単になります。
        
              
        
              P(X = 0) ＝ e^(−λ)
              
        
              
          これが金額単位サンプリングの出発点です。
          「これだけの誤謬が潜んでいたとして、1件も引っかからない確率」を表しています。
          この確率を、あらかじめ決めた受入リスク RIA に一致させるように λ を決める——
          それが理論編で出てくる CF(0) = −ln(RIA) です。
        
              
        
              
          
              
            誤解
            
              ポアソン分布は二項分布より大ざっぱな、簡便法だ。
              
          
              
          
              
            正しくは
            
              条件（回数が多く確率が小さい）が満たされていれば、答えはほとんど変わりません。上の表のとおりです。逆に統制テストのように件数が25件程度と少ない場面でポアソンを使うと、答えがずれて結論が変わることがあります。だから使い分けています。
              
          
              
        
              
      
              
    
              

    
              
      05「90%の信頼度」と対数
      
              
        
              信頼度が意味すること・しないこと
              
        
              
          「90%の信頼度」という言い方は、監査でも頻繁に出てきます。
          ただし、その意味はしばしば誤解されています。
        
              
        
              
          
              
            よくある誤解
            
              「上限逸脱率8.8%」と出たとき、真の逸脱率が8.8%以下である確率が90%ある。
              
          
              
          
              
            正しくは
            
              真の逸脱率は、私たちが知らないだけですでに決まっている一つの数です。決まっているものに「確率90%」とは言えません。90%が指しているのは手続のほうの性質です。「この上限の求め方を何度も繰り返せば、90%の場合には本当の値を下回らない上限が出る」——そういうやり方を使っている、という意味になります。
              
          
              
        
              
        
              
          実務ではこう理解して差し支えありません
          「この手続で出した上限は、10回に1回くらいは本当の値より低く出てしまう。
          その程度の危うさを承知のうえで使っている」。
          この理解であれば、判断を誤ることはまずありません。
        
              
        
              
          なお監査で使うのは上限だけです。統計の教科書に出てくる信頼区間は
          「◯%から◯%のあいだ」と上下を挟みますが、監査人が知りたいのは
          「悪くてもどこまでか」だけなので、下側は見ません。これを片側といいます。
        
              

        
              対数（ ln ）と定数 e
              
        
              
          式に出てくる ln は自然対数と読みます。やっていることは1つだけです。
        
              
        
              
          ln が答えていること
          「e を何乗すれば、その数になりますか」——これだけです。
          e は円周率πと同じような決まった数で、およそ 2.718 です。
        
              
        
              
          −ln(0.10) = 2.30 というのは、
          「e を −2.30 乗すると 0.10 になる」ということです。
          電卓の LN キーで 0.1 を入れると −2.302585 と表示されますので、実際に確かめられます。
          確率は必ず1より小さく、対数が必ずマイナスになるため、
          扱いやすいようにマイナスを付けて正の数にしています。
        
              

        
              なぜ対数が出てくるのか
              
        
              
          前の節で P(X = 0) = e^(−λ) という式が出てきました。
          ここで知りたいのは逆向きです。「0回の確率をちょうど10%にしたい。λ はいくつか」。
        
              
        
              e^(−λ) ＝ 0.10   を λ について解きたい
    ↓  両辺で「e を何乗したか」を見る
−λ ＝ ln(0.10) ＝ −2.302585
    ↓
 λ ＝ 2.302585
              
        
              
          対数は、指数の形で書かれた式から「何乗か」を取り出すための道具です。
          掛け算が足し算に変わるという性質も、ここから来ています
          （e^2 × e^3 = e^5 なので、対数にすると 2 + 3 = 5 になります）。
        
              
        
              
          この λ = 2.30 が信頼係数 CF です。理論編では
          「RIA を半分にすると CF に 0.693 が足される」という性質を使いますが、
          その 0.693 は ln(2) のことです。
          掛け算（半分にする）が、対数の世界では足し算になる——
          その一例だとお考えください。

      02なぜ監査リスクを数値で置くのか
      
              
        
              
          多くの法人は固有リスク・統制リスクを「低・中・高」の3段階で評価します。
          それなのにこのツールが 0.3 / 0.5 / 0.7 のような数値入力を求めるのは、
          監査リスクモデルが掛け算と割り算でできているからです。
        
              
        
              DR = AR ÷ (IR × CR)
              
        
              
          「低・中・高」という区分は、大小の順序を表しているだけです。
          「中は低の何倍か」が決まっていないため、掛けることも割ることもできません。
          数値を入れるのは、監査人の判断を精密にするためではなく、
          判断を割り算に載せられる形に置き直すためです。判断の粒度は3段階のままで構いません。
        
              

        
              
          この式の位置づけ
          注意しておきたいのは、AR = IR × CR × DR は
          監査基準が定めた等式ではないということです。
          監査基準報告書200 A35 は「監査リスクの要素に関する一般的な関係を数量的に表すモデルを
          利用することがある」と述べており、利用を認めてはいますが義務づけてはいません。
          平成14年の監査基準改訂意見書も、掛け算の等式は示さず
          「これらのリスクは、実際には複合的な状態で存在することもあり、必ずしも明確に切りわけられるものではない」
          と留保しています。同 A31 も「リスク評価は、正確に測定できるものではなく、
          職業的専門家としての判断に係る事項である」としています。
          
              
          つまりこの式は基準が使用を容認する道具であって、
          割り算の結果が判断を代替するわけではありません。
        
              
        
              
          なお現行の監査基準報告書200 第12項(5)では、監査リスクはまず
          「重要な虚偽表示リスク × 発見リスク」の2つに分けられます。
          固有リスクと統制リスクへの分解は、監査基準報告書315 第5項が求める二段階目の分解です。
        
              

        
              
          直感的には
          このモデルがやっているのは割り当ての計算です。監査全体で許せる見逃しの余地（AR）がまず決まっている。
          そのうち会社側の事情（IR）と統制の弱さ（CR）が重なってすでにどれだけ食いつぶしているかを見る。
          残りいくらを実証手続に配れるか — それが発見リスクです。残りが多ければ手続は軽く、少なければ重くなります。
        
              

        
              
          どの数値を当てるかは各法人の監査マニュアルが定めるもので、このツールが決めるものではありません。
          だからこそ対応表を内蔵せず、数値を直接入力させています。
        
              

        
              数値にすると何が見えるか
              
        
              
          DRは実証手続全体に残された発見リスクであり、MUSだけの受入リスクRIAと同じではありません。
          分析的実証手続、詳細テストその他の手続へリスクをどう配分するかを監査計画で検討し、RIAを別途設定します。
          次は、母集団簿価5億円・許容誤謬1,500万円・期待誤謬0で、RIAだけを変えた場合の例です。
        
              
        
              
          
              
            
              設定したRIA信頼度CF選択ポイント数
              
            
              
              20%80%1.6154
              
              
              15%85%1.9064
              
              
              10%90%2.3077
              
              
              5%95%3.00100
              
              
              1%99%4.61154
              
                          
          
              
        
              
        
              
          RIAを下げるほど、誤って受け入れるリスクを小さくするため選択ポイント数が増えます。
          どのRIAが適切かは、この表の件数から逆算せず、監査計画と所属法人等のメソドロジーに従って先に決めます。
        
              

        
              覚えておくと使える性質
              

        
              覚えておくと使える性質
              
        
              
          後述のとおり CF = −ln(RIA) なので、RIA を半分にすると CF には ln2 ≒ 0.693 が「足され」ます。
          掛け算ではなく足し算です。したがって増える件数は
        
              
        
              増加件数 = (BV ÷ TM) × 0.693 = (5億 ÷ 1,500万) × 0.693 ≒ 23件
              
        
              
          となり、出発点がどこでも同じだけ増えます。実際、上の表と同じ前提では
          RIA 20%→10% で +23件、10%→5% でも +23件、4%→2% でも +23件です。
          「リスク評価を一段厳しくすると何件増えるか」は、倍率ではなく件数の足し算で覚えるほうが実務では役に立ちます。
        
              

        
              
          
              
            誤解
            
              IR を 0.5 から 0.55 に変えるような細かい調整に意味がある。
              
          
              
          
              
            正しくは
            
              数値は判断の代用ではなく、判断を計算につなぐ翻訳にすぎません。0.5 と 0.55 の差に監査的な意味はありません。3段階の判断を3つの数値に対応させれば十分です。
              
          
              
        
              
      
              
    
              

    
              
      03統制テスト：なぜ二項分布なのか
      
              
        
              
          統制テストでは、抽出した証憑1件ごとに「承認印があるか・ないか」「照合されているか・いないか」を見ます。
          結果が二択で、それを n 件繰り返す。これは二項分布が想定している構造そのものです。
        
              

        
              
          上限逸脱率とは何か
          統制テストで問うているのは「この統制は何％効いているか」ではありません。
          「どこまで悪い可能性を、今日の結果で否定できたか」です。
          25件を抜いて逸脱が1件も出なければ、真の逸脱率が20%の母集団だとは考えにくくなります。15%でも同じです。
          しかし8.8%あたりまで下げてくると、「25件すべて問題なし」も十分にありうる話になり、もう否定できません。
          この否定できなくなる境界が上限逸脱率 ULD です。
        
              

        
              
          だから逸脱0件でも ULD は0%になりません。
          見ていない残りの証憑に逸脱が潜んでいる可能性を、25件という枚数では消しきれないからです。
          ULD が下がるのは統制が良くなったからではなく、監査人が見た枚数が増えて否定できる範囲が広がったからです。
        
              

        
              なぜ正規近似ではなく正確二項なのか
              
        
              
          統計の教科書に出てくる信頼区間の多くは正規分布による近似です。しかし統制テストの条件では、この近似が壊れます。
        
              
        
                
          
              • サンプル数が25〜116件程度と小さい
                • 
          
              • 逸脱率が0のすぐ近くにある
                • 
        
              
        
              
          逸脱率が0に近いところでは、逸脱件数の散らばり方が左右対称になりません（0より下がないので左に潰れます）。
          左右対称を前提とする正規近似は、この潰れた形をそのまま扱えません。
          極端な話、逸脱0件だと最も素朴な正規近似は「上限0.00%」という無意味な答えを返します。
        
              
        
              そこで近似を挟まず、二項の確率をそのまま足し上げて境界を求めます。
              
        
              n   = min{ n : P(X ≤ x | n, TDR) ≤ ROO }
ULD = BetaInv(1 − ROO, x + 1, n − x)
              
        
              
          BetaInv は「逸脱が x 件以下になる確率」を逸脱率について逆に解いたもので、
          この逆解きがベータ分布の分位点と一致することが数学的に知られています（Clopper–Pearson の名で呼ばれます）。
          本ツールは内部で二項の確率を直接使い、該当する逸脱率を数値的に探しています。
        
              

        
              近似との差は実際どれくらいか
              
        
              
          許容逸脱率5%・逸脱0件の設計（45件）で、「真の逸脱率がちょうど5%でも逸脱が1件も出ない確率」＝過信リスクの実質を比べます。
        
              
        
              正確二項  0.95^45          = 9.94%   → 判断基準10%をぎりぎり下回る
ポアソン近似 e^(−45×0.05) = 10.54%  → 基準を超えてしまう
              
        
              
          わずか0.6ポイントの差ですが、結論が反転します。
          実証手続の側では後述のとおりポアソンを使いますが、統制テストで同じことをすると
          サンプル数が足りないのに足りていると判断しかねません。分布を使い分けるのはこのためです。
        
              

        
              知っておきたい2つのただし書き
              
        
              
          
              
            厳密には
            
              証憑は抜いたら戻さないので、本当の姿は超幾何分布（1件抜くと母集団の中身がその分減る前提の分布）です。ただし二項で計算すると上限逸脱率は必ず安全側（高め）に出ます。母集団が5,000件で25件を抜くなら差はほぼありませんが、母集団100件から25件だと二項は明確に保守的になります。
              
          
              
          
              
            式と表
            
              過信リスク10%かつ許容逸脱率5%・7%・9%という最も使う組合せでは、上の式ではなく実務で定着している標準サンプル数表を採用しています。表の値は式の最小値と同じかそれより多く（許容逸脱率5%・予想逸脱2件では式が105件、表は116件）、いずれも ULD ≤ 許容逸脱率 を満たします。それ以外の条件では式から直接算出します。
              
          
              
        
              
        
              
          なお母集団250件未満かつ日次以外の統制では、頻度別ルール（週次5件・月次2〜3件など）に切り替わります。
          こちらは統計的サンプリングではないため、この節の議論は当てはまりません。
          該当する場合は計算画面の「サンプリング区分」にその旨を表示します。
        
              
      
              
    
              

    
              
      04実証手続：なぜポアソン分布なのか
      
              
        
              
          金額単位サンプリング（MUS）では、母集団を件数ではなく金額で捉えます。
          5億円の売掛金なら、5億個の「1円」が並んでいると考え、その1円1円を抽出単位とみなします。
        
              

        
              
          直感的には
          証憑の束を枚数で数えるのが統制テストです。1枚ごとに承認印の有無を見るので、単位は枚、答えは二値、分布は二項になります。
          MUS は同じ母集団を金額の目盛りとして捉えなおします。
          5億円を1円ずつ並べたものと考え、一定の金額ごとに1件ずつ抽出していきます。
          誤謬はこの5億個の並びのなかに、ごくまばらに混じっています。
          めったに現れないものが、抽出のたびに何個当たるかを扱うのがポアソン分布です。
        
              

        
              ポアソン分布は「機会は無数にあるが、めったに起きない出来事が平均して何回起きるか」を表します。MUS はまさにその状況です。
              
        
                
          
              • 抽出単位の数 n が極めて大きい（5億個）
                • 
          
              • 1単位あたりが誤っている確率 p が極めて小さい
                • 
        
              
        
              
          この条件（n→大、p→小、平均 np は一定）では、二項分布はポアソン分布でよく近似できます。
          二項分布は n と p の2つを持ち歩く必要がありますが、ポアソンなら
          平均何個混じるかという1つの数字 λ だけで議論できます。
          母集団の絶対的な大きさを気にしなくてよくなる、というのがポアソン分布を使う利点です。
        
              
        
              
          統制テストが二項分布で、実証手続がポアソン分布なのは矛盾ではありません。
          同じ母集団を「枚数」で見るか「金額」で見るかの違いです。
          金額で見ると単位の数が桁違いに増えるため、ポアソン分布が使えるようになります。
        
              

        
              部分的な誤りはどう扱うか
              
        
              
          実務で見つかる誤謬は、伝票まるごとが誤りというより、金額の一部が誤っている場合がほとんどです。
          簿価80万円の伝票のうち20万円分が誤っていれば、その伝票の25%が誤っていることになります。
          この割合を 汚染率 = 誤謬額 ÷ その項目の簿価 として求めます。
          英語の taint（テイント）の訳語で、金額単位サンプリングの標準的な用語です。
        
              
        
              
          
              
            誤解
            
              汚染率は「誤謬額 ÷ サンプリング間隔 SI」で求める。
              
          
              
          
              
            正しくは
            
              分母はその項目の簿価です。分母を取り違えると推定誤謬が数倍ずれます。なお項目の簿価が SI 以上の場合は、その項目が必ず抽出されるため、母集団全体への引き伸ばしをせず誤謬額をそのまま使います。
              
          
              
        
              

        
              前提が崩れるとき
              
        
              
          ポアソンが使えるのは「誤謬がまれで、互いに独立に散らばっている」ときです。
          特定の担当者や特定の期間に誤謬が集中している場合、近似の議論以前にサンプリングの前提自体が成り立ちません。
          本ツールは誤謬が10件を超えると前提崩壊として警告します。計算は続行され上限値としては依然有効ですが、
          その上限が実務判断に使えるほど絞り込めなくなります。
        
              
      
              
    
              

    
              
      05式の意味：CF と サンプル数
      
              
        
              ここが本ツールの中心です。まず自然対数の記号から。
              
        
              
          ln は自然対数で、「e を何乗したらこの数になるか」を返します。
          e は約2.718という定数です。確率は1未満なので対数は負になり、正の係数にするためマイナスを付けて
          −ln(RIA) と書きます。電卓の LN キーで確認できます。
        
              
        
              CF(0) = −ln(RIA)

RIA = 20%  →  CF(0) = 1.61
RIA = 10%  →  CF(0) = 2.30
RIA =  5%  →  CF(0) = 3.00
RIA =  1%  →  CF(0) = 4.61
              

        
              CF はどこから来るのか
              
        
              
          ポアソン分布で、平均 λ 件の誤謬が潜んでいるとき、抽出網に1件もかからない確率は
          e^(−λ) です。これが受入リスク RIA にちょうど等しくなるような λ を求めます。
        
              
        
              e^(−λ) = RIA   を λ について解くと   λ = −ln(RIA)
              

        
              
          つまり CF とは
          「誤謬が1件も出ないまま手続を終えても、見逃し確率が RIA に収まる潜在誤謬量」です。
          手続を終えて誤謬がゼロだったとき、監査人は「だから誤謬はない」とは言えません。
          言えるのは「これだけ見て何も出ないのだから、潜んでいるとしてもせいぜいこの程度だ」ということだけ。
          その"この程度"を表したのが CF です。
        
              

        
              
          添字の 0 は「誤謬が1件も出なかったとき」を意味します。
          誤謬が出た後の評価では CF(1)、CF(2)… を使いますが、これらは −ln(RIA) の単純な倍数ではなく、
          別途ポアソン分布から解きます（RIA=10% なら CF(0)=2.30, CF(1)=3.89, CF(2)=5.32）。
        
              
        
              
          なお CF の単位は「件数」ではなく「SI 何個分の誤謬額か」と読むのが正確です。
          簿価まるごとが誤謬（汚染率100%）の項目に換算したときだけ件数として読めます。
        
              

        
              サンプル数と間隔
              
        
              SI = (TM − EM × EF) ÷ CF(0)      … 何円ごとに1件抜くか
n  = BV ÷ SI = BV × CF(0) ÷ (TM − EM × EF)
              
        
              
          言葉にするとこうなります。許容誤謬から期待誤謬の割増分を差し引いた残りを、CF で割る。
          そうして出てくる金額が SI です。母集団をこの金額ごとに区切っていくと、区切りの数がサンプル数になります。
        
              
        
              
          期待誤謬 EM は分母からのみ差し引きます。分子に掛けることはしません。
          EM が増えるほど分母が縮み、サンプル数は増えます。
          EM × EF が TM 以上になると分母が0以下になり、サンプリング自体が成立しません。
        
              

        
              
          監査人が決めるのは RIA だけ
          監査人が判断で決めるのは RIA です。CF はそこから自動的に計算される値で、直接設定する数字ではありません。
          リスクを絞る（RIA を下げる）と CF が大きくなり、SI が小さくなって、必要なサンプル数が増える。
          この順に一方向でつながっています。
        
              

        
              基本精度は許容誤謬から自動的に決まる
              
        
              
          誤謬評価の出発点である基本精度は CF(0) × SI ですが、
          SI の定義を代入すると CF が約分され、次の恒等式になります。
        
              
        
              基本精度 = CF(0) × SI = CF(0) × (TM − EM×EF) ÷ CF(0) = TM − EM × EF
              
        
              
          つまり基本精度は許容誤謬から、RIAに対応するEFで拡大した期待誤謬を引いた額です。
          EMが0ならTMと一致しますが、EMがある場合はEFを介してRIAの設定にも影響されます。これは、誤謬が見つからなくても残るサンプリングリスクへの取り置きです。
        
              

        
              
          
              
            重要な帰結
            
              期待誤謬を 0 と置くと、基本精度は許容誤謬とぴったり一致します。誤謬に使える余白はゼロです。この設計で過大計上誤謬を発見すると、推定誤謬上限は許容誤謬を超え、監査アプローチの再評価が必要になります。
              
          
              
          
              
            対処
            
              誤謬の発生が見込まれるなら、必ず期待誤謬を設定してください。EM=300万円なら基本精度は 1,500万 − 300万×1.6 = 1,020万円 となり、残る480万円が「見つかるであろう誤謬」の取り置きになります。計算画面でも EM=0 のときは警告を出します。
              
          
              
        
              

        
              拡大係数 EF は受入リスクに応じて変わる
              
        
              
          EFは期待誤謬の不確実性を取り置くため、受入リスクに対応する表から選ぶ係数です。
          監査基準報告書530 研究文書第1号6-4の考え方に合わせ、本ツールは選択したRIAから次の値を使用します。
        
              
        
              受入リスク RIA   1%    5%    10%   15%   20%   25%
拡大係数 EF      1.90  1.60  1.50  1.40  1.30  1.25
              
        
              
          たとえばRIA=10%ならEF=1.50、RIA=5%ならEF=1.60です。表にない値は隣接する値から補間します。
          固定値1.6をすべてのRIAへ流用しないため、期待誤謬の取り置きと選択ポイント数が設定した受入リスクに連動します。
        
              
        
              
          数値の位置付け
          この表とMUSの式は一つのモデルです。所属法人等が別の信頼係数表、拡大係数又は設計方法を採用している場合は、そちらを優先してください。
        
              

        
              MUS の2つの前提
              

        
              MUS の2つの前提
              
        
                
          
              • 開始点は無作為に選ぶ — SI ごとに区切っていくとき、最初の1点は 0円〜SI円 の間から無作為に選びます。1円目から機械的に始めると、無作為抽出になりません。
                • 
          
              • SI 以上の高額項目は必ず抽出される — 簿価が SI より大きい項目は、等間隔で区切れば必ず1回以上は選ばれます。実務ではこれらを特定項目として先に取り出し、残りに MUS を適用します。本ツールも③のステップで控除できます。
                • 
        
              
      
              
    
              

    
              
      06誤謬を見つけたあと：UML の組み立て
      
              
        
              推定誤謬     = taint × SI （簿価 ≥ SI なら誤謬額の実額）
増分許容誤謬 = Σ (CF(i) − CF(i−1) − 1) × 推定誤謬_i
               ※ 対象は簿価 < SI の項目のみ。汚染率の高い順に並べる
UML          = 基本精度 + Σ推定誤謬 + 増分許容誤謬
              
        
              UML は次の3つを足し合わせたものです。
              
        
                
          
              • 基本精度：誤謬が1件も出なくても残る、見ていない部分の余白。前節のとおり TM − EM×EF に一致します。
                • 
          
              • Σ推定誤謬：見つけた誤謬を母集団全体に引き伸ばした額。
                • 
          
              • 増分許容誤謬：誤謬が出たことで、まだ見ていない部分にも同種の誤謬が潜む可能性が高まった分の上乗せ。
                • 
        
              
        
              
          増分の係数 CF(i) − CF(i−1) − 1 は、RIA=10% なら1件目0.587、2件目0.433、3件目0.359…と減っていきます。
          件数が増えるほど1件あたりの上乗せは小さくなるので、UML が膨らむ主因は増分ではなく Σ推定誤謬のほうです。
        
              

        
              高額項目に上乗せは発生しない
              
        
              
          なぜ除くのか
          簿価が抽出間隔 SI 以上の項目は、等間隔に刻めば必ず抽出されます。
          必ず見ているのですから、そこにサンプリングリスクは存在しません。
          「見ていない部分にも同じ誤謬が潜んでいるかもしれない」という上乗せの理由が、そもそも成り立たないのです。
        
              
        
              
          監査基準報告書530 研究文書第1号 6-7 も
          「サンプル抽出間隔以上のサンプルから発生したエラーは、そのすべてがサンプル項目として
          抽出されていますので、上限精度の増加高はありません」と述べています。
          したがって高額項目の誤謬は、推定誤謬額には実額で加えますが、増分許容誤謬の対象からは外します。
          並べ替えの順位からも外すため、通常サンプルの側が本来の係数を受け取ります。
        
              

        
              過大計上と過小計上は分けて集計する
              
        
              
          簿価より監査後価値が小さければ過大計上、大きければ過小計上です。
          両者は打ち消し合わせず、それぞれ別に UML を算定して両方を評価します。
          相殺してしまうと、方向の違う誤りが偶然釣り合っただけの母集団を「問題なし」と判断しかねないためです。
        
              

        
              
          サンプリングリスクは消えない
          誤謬ゼロで手続を終えても、真の誤謬額が許容誤謬を超えている可能性は RIA（たとえば10%）だけ残ります。
          これは手続の不備ではなく、一部しか見ないという手法が構造的に抱えるリスクそのものです。
          サンプリングは「確実にする手続」ではなく「不確実さを測って管理下に置く手続」だと理解してください。

      08サンプリング実施前の留意点
      
              
        
              特定項目抽出
              
        
              
          金額的重要性が高い項目、不正リスクが高い項目、異常な取引等は、サンプリングとは別に
          特定項目として全件抽出して検証します。閾値は許容誤謬に対する百分率の1系統のみです。
        
              
        
              階層化
              
        
              
          母集団に異なる特性を持つ項目が混在する場合、同質的な部分母集団に階層化して
          それぞれからサンプリングすることで、サンプル数を削減しつつ監査の有効性を高められます。
        
              
        
              母集団の網羅性確認
              
        
              
          サンプリング対象の母集団が監査対象期間の全取引を網羅的に含んでいることを確認し、
          データの完全性と正確性を検証してください。
          この確認なしにサンプリング結果を母集団全体へ推定することはできません。
        
              
        
              統計的厳密性と実務慣行
              
        
              
          両者が衝突する場合、本ツールは実務慣行を採用したうえで、算定根拠にその旨を明記し
          統計的裏付けがないことを開示します（例：月次統制2件ルール）。
          保守側か効率側かで迷う場合はサンプル数が多くなる側を採ります。

      「AIで全件を分析できるなら、サンプリングは要らなくなるのではないか」という問いは、
      監査の現場でも頻繁に聞かれます。結論から言えば、
      サンプリングは不要になるのではなく、適用される場所が移ります。
      このページでは、その理由を監査基準の組み立てと全件分析の限界の両面から整理します。
    
              

    
              
      01そもそも基準はサンプリングをどう位置づけているか
      
              
        
              
          見落とされがちですが、監査基準はもともとサンプリングを唯一の方法とはしていません。
          抽出方法を定めているのは監査サンプリングの基準ではなく、
          監査基準報告書500「監査証拠」です。同 A52項は、監査手続の対象項目の抽出方法として
          次の3つを並列に置いています。
        
              
        
                
          
              • 精査（100%の検討）
                • 
          
              • 特定項目抽出による試査
                • 
          
              • 監査サンプリングによる試査
                • 
        
              
        
              
          同 A53項は、精査が適切となりうる場合として
          「母集団が少数の金額的に大きい項目から構成されている場合」
          「特別な検討を必要とするリスクが存在する場合で、他の方法では十分かつ適切な監査証拠を入手することができない場合」
          「情報システムによって自動的に行われる反復的な性質の計算等、精査が費用対効果の高い方法である場合」
          の3つを挙げています。
        
              
        
              
          ここが出発点
          全件を検討すること自体は、AIが登場する前から基準が認めている選択肢です。
          したがって「全件分析ができるようになった」ことは、
          基準の枠組みそのものを変える話ではありません。
          変わるのは「どの方法が現実的に選べるか」という実行可能性のほうです。
        
              
        
              
          サンプリングの基準である監査基準報告書530も、第1項で
          「本報告書は、監査人が監査手続の実施において監査サンプリングを利用する場合に適用する」
          と述べています。サンプリングの実施を義務づける基準ではありません。
          国際基準の ISA 530 も同じ構成で、第1項は
          「監査人がサンプリングを利用すると決定した場合に適用される」となっています。
        
              
        
              
          監査サンプリングが必要になるのは、
          抽出した一部の結果から母集団全体について結論を出したいときだけです。
          全件を見たのなら母集団全体について直接わかるので、推定は要りません。
          ここまでは「AIでサンプリングが不要になる」という主張が正しい範囲です。
        
              
      
              
    
              

    
              
      02「全件処理した」と「全件確かめた」は違う
      
              
        
              
          問題は、データ分析でいう「全件」が、監査でいう「心証を得た」と同じ意味ではないことです。
          仕訳100万件にルールを当てて例外を1,000件抽出したとき、
          処理は全件に及んでいますが、確かめたのは「そのルールに照らして異常か」だけです。
        
              

        
              全件分析をしても別途確かめる必要が残るもの
              
        
              
          
              
            母集団
            
              データの完全性・正確性。分析にかけたデータが対象期間の全取引を漏れなく含み、
              かつ正確であることは、分析そのものからは出てきません。会社が作成したデータ（IPE）を使う以上、
              その信頼性の検証が前提として必要です。ここが崩れると、全件分析の結論はまるごと成立しません。
              
          
              
          
              
            ルール
            
              判定ロジックの妥当性。「何を異常とみなすか」を決めているのは人です。
              ルールが取りこぼす類型は、何件処理しても永久に検出されません。
              網羅的に処理したことと、網羅的な観点で見たことは別です。
              
          
              
          
              
            例外
            
              抽出された例外の評価。1,000件の例外が出たとき、
              その全件に証憑突合を行えるとは限りません。
              実務では例外の中からサンプリングすることになり、ここでサンプリングが復活します。
              誤検知（false positive）が多いほどこの負荷は増えます。
              
          
              
          
              
            実態
            
              データに写らない事実。証憑の真正性、契約条件、取引の経済的実態、
              関連当事者性、経営者の見積りの合理性は、仕訳データの中には書かれていません。
              簿外取引や共謀は、そもそも母集団に現れないという性質を持ちます。
              
          
              
        
              

        
              
          このため、全件分析は「例外候補を漏れなく挙げる」ところまでを担い、
          そこから先の心証形成は従来どおり人の手続に戻ります。
          監査証拠の十分性と適切性を判断するのは、依然として監査人です。
        
              

        
              基準設定主体も同じことを述べています
              
        
              
          IAASB が2023年2月に公表した非権威的支援資料（ATT 利用時の例外調査と手続実施上の重要性に関する FAQ）は、
          「母集団全体に自動化されたツールを適用した場合でも手続実施上の重要性は適用される」
          と回答しています。理由として挙げられているのは次の点です。
        
              
        
                
          
              • 当該手続がアサーション・レベルの重要な虚偽表示を発見するよう設計されていない場合がある（リスク評価手続として設計されている等）
                • 
          
              • 関連するすべてのアサーションを対象としていない場合がある（計上済み母集団に対して実施され、網羅性を扱っていない等）
                • 
          
              • 経営者による内部統制の無効化などの不正リスクを扱っていない場合がある
                • 
          
              • データのクレンジング等により、母集団全体を表すデータに対して実施されていない場合がある
                • 
          
              • 母集団の理解不足、人員配置、監督・査閲、実行の巧拙など、手続の立案・実施に関するその他の限界
                • 
        
              
        
              
          同資料は、例外に該当しなかった項目についても
          「監査人は依然として母集団について十分かつ適切な監査証拠を入手する必要がある」としています。
          また IAASB が2020年11月に公表した ISA 315 関連の FAQ は、
          「これらのツールがいかに強力であっても、監査人の知識及び職業的専門家としての判断の代替とはならない」
          と明記しています。
        
              
        
              
          米国では PCAOB が2024年6月に、電子的情報のテクノロジー利用分析に関する基準改訂を採択しました
          （2025年12月15日以後に開始する事業年度から適用）。
          採択リリースは、母集団全体の分析で調査対象項目が識別されなかった場合について
          「事実と状況は多様であるため、十分かつ適切な監査証拠を提供するシナリオを特定することはできない」と述べ、
          請求数量と出荷数量を突合する全件分析に加えて
          外部情報源から受領した情報（注文書、入金記録等）のサンプルを検証するといった他の監査手続が必要となることがある、
          と例示しています。
        
              
      
              
    
              

    
              
      03大手監査法人のツールは何をしていると言っているか
      
              
        
              
          4大監査法人はいずれも監査データ分析（Audit Data Analytics）の基盤を持っています。
          Deloitte の Omnia、PwC の Halo、EY の Helix、KPMG の Clara などが知られています。
        
              
        
              
          日本語の公表資料を見ると、訴求の中心は
          「リスクの高い領域を絞り込む」「異常を早期に発見する」「監査の質を高める」に置かれています。
          PwC Japan の「次世代監査で活用されるテクノロジー」は Halo を
          「膨大なデータの分析を可能とすることで、リスク評価やデータ分析、監査手続の高度化を実現し、
          価値あるインサイトを引き出すことができる監査システム」と説明しており、
          ページ内に「サンプリング」の語は一度も出てきません。
          EY新日本も GL Analyzer について「全ての仕訳データを分析することで、変動や通例でないパターンを識別し、
          ポイントを絞ったリスク評価手続をサポート」と、リスク評価手続としての位置づけで説明しています。
        
              
        
              
          一方で、英語圏には踏み込んだ表現もあります。EY US は2023年に
          「データドリブンな監査 ― 統計的サンプリングではなく、クライアントのデータの全母集団の分析に依拠する監査 ― は強靭である」
          と述べています。KPMG のあるページには
          「すべての取引をスキャンする ― もはやサンプルではない」という見出しと、
          「AIの利用は分析が必要なサンプルサイズを削減する」という記述が同じページに併存しています。
        
              
        
              
          確認するとよいこと
          同一ページ内で「サンプルではない」と「サンプルを減らす」が同居することからも分かるとおり、
          この種の文言は監査手続上の厳密な位置づけを示したものではありません。
          自法人のツールを評価するときは、宣伝文ではなく
          「この分析でどの監査要点について、どこまでの心証が得られるのか」を、
          手続の設計書と品質管理の文書で確認してください。
        
              
      
              
    
              

    
              
      04サンプリングはどこへ移るのか
      
              
        
              
          全件分析を取り入れた場合、母集団は次のように層に分かれていきます。
          サンプリングは消えるのではなく、いちばん下の層に降りていきます。
        
              
        
              母集団
 ├─ 全件分析で異常なしと判定された領域   → 分析の信頼性そのものを検証する
 ├─ 特定項目（高額・不正リスク・異常取引） → 全件検証する
 ├─ 抽出された例外項目                    → 件数が多ければ ここでサンプリング
 └─ 残余母集団                            → ここでサンプリング
              
        
              
          本ツールの③「特定項目控除」は、まさにこの構造を扱うためのステップです。
          特定項目を母集団から差し引き、残余母集団に対してサンプル数を算定します。
          全件分析の適用範囲が広がるほど残余母集団は小さくなり、必要なサンプル数も減ります。
          減りますが、ゼロにはなりません。
        
              
        
              件数基準の慣行はどうなるか
              
        
              
          日本の統制テストで定着している「25件」「月次統制なら2〜3件」といった件数基準は、
          統制が有効に運用されているかを確かめるための基準であり、
          取引データの全件分析とは層が異なります。
          自動化された統制であれば、母集団全体に同じロジックが適用されている以上、
          少数のサンプルで足りるという議論も従来からあります。
          一方、手作業による統制や判断を伴う統制については、件数基準の考え方が引き続き当てはまります。
        
              
      
              
    
              

    
              
      05新しく生まれるリスク
      
              
        
              
          AIの利用は、既存のリスクを減らす一方で、監査人側に新しい注意点をもたらします。
        
              
        
                
          
              • 出力への過信 — 自動化されたツールの出力を、検証せずに正しいものとして受け入れてしまう傾向は
            automation bias として知られています。「システムが異常なしと言ったから異常なし」は監査証拠になりません。
                • 
          
              • ブラックボックス化 — 判定の根拠を説明できないモデルを使うと、
            監査調書に「なぜそう結論したか」を記載できなくなります。
            監査は結論だけでなく、そこに至る過程の記録を求めます。
                • 
          
              • 重要な例外が埋もれる — 誤検知が大量に出ると、本当に見るべき項目が紛れてしまいます。
            例外を減らすためにルールを緩めると、今度は取りこぼしが増えます。
                • 
          
              • ツールの信頼性そのものの検証 — 分析ツールが正しく動作していることを
            どう確かめるかという問題が新たに生じます。
                • 
        
              

        
              例外を「見なかったことにする」問題
              
        
              
          英国 FRC が2021年に公表したガイダンスは、
          outliers（当初の期待に合致しなかった結果）と exceptions（分析後に真に例外と判断したもの）を区別したうえで、
          「多くの場合この outlier の量は、定義が不十分なパラメータの症状である」と指摘しています。
          そのうえで、パラメータを調整する動機として不適切なものを3つ挙げています。
        
              
        
                
          
              • 作業量を人為的に削減するため
                • 
          
              • 前年と同数の outlier に合わせるため
                • 
          
              • データ品質が低いと分かっているのに例外数を減らすため
                • 
        
              
        
              
          IAASB が2025年に公表した論点整理には、監査規制当局からの懸念として
          「監査人は見てしまったものを見なかったことにはできない」という指摘が記録されています。
          全件分析で例外を識別しておきながら、それを無視して従来型の代替手続に戻ることは適切でない、という趣旨です。
        
              
        
              
          学術研究でも、全件分析は実務上処理しきれない量の例外を生むことが繰り返し報告されています。
          また、抽出されなかった取引は「理論上リスクが低いと仮定されている」にすぎず、
          潜在的な異常が残存しうる点も指摘されています。
          実務調査では、データ分析の出力は主として補足的な監査証拠として扱われ、
          それ単独を唯一の監査証拠とすることは品質管理上承認されていなかった、という報告もあります。
        
              

        
              エージェント型AIで難しさが増す点
              
        
              
          業界紙 Accountancy Age は2026年4月、EY が EY Canvas に
          多段階のエージェント型AIフレームワークを統合したと報じました。
          同紙によれば、150か国以上・16万件の監査業務が対象で、
          年間1.4兆行の仕訳データを処理し、2028年までにエンドツーエンドの監査活動をAIで支援する計画とされています
          （いずれも同紙の記載であり、監査法人の公表資料で確認したものではありません）。
        
              
        
              
          記事は「業界は100%母集団テストへ向かっている」と表現していますが、
          これは記事の著者による整理であり、監査手続上の位置づけとして示されたものではありません。
          同じ記事のなかで、英国 FRC の立場として
          「人間の判断が最終的な決め手であることに変わりはない」が引かれ、
          法的責任は人間の監査人が負うと述べられています。
        
              
        
              
          従来の分析ツールとの違い
          同記事は懸念として、エージェント型AIは不透明でありうる（常に「途中の作業」を見せてくれるとは限らない）点と、
          ハルシネーション（論理解釈の誤り）のリスクを挙げています。
          ここが従来のルールベースの分析と質的に異なる点です。
          判定ルールが明示されていれば「なぜこの項目が例外なのか」を調書に書けますが、
          複数の手順を自律的に進めるAIでは、その経路自体を記録・再現することが難しくなります。
          監査は結論だけでなく、そこに至る過程の記録を求めます。
          導入を検討する際は、精度よりも先に「何を調書に残せるか」を確かめてください。
        
              

        
              
          サンプリングの本質は変わらない
          サンプリングは「手を抜くための手続」ではなく、
          限られた資源のもとで、結論の不確かさを測って管理下に置くための手続です。
          全件を見られるようになっても、見たものが何を意味するかを判断する仕事は残ります。
          むしろ、分析の前提が正しいかを確かめる場面で、
          サンプリングの考え方が今まで以上に必要になります。
        
              
      
              
    
              

    
              
      06実務でどう整理するか
      
              
        
              監査計画を立てるとき、次の順で考えると整理しやすくなります。
              
        
                
          
              1. その母集団は全件分析に向いているか — データが構造化されていて、
            判定ルールを明確に書けるか。書けないなら従来どおりの手続です。
                2. 
          
              2. データの完全性・正確性をどう確かめるか — ここを飛ばすと以降がすべて崩れます。
                3. 
          
              3. 全件分析で何が言えて、何が言えないか — 監査要点ごとに切り分けます。
                4. 
          
              4. 特定項目として抜き出すものは何か — 本ツールの③に対応します。
                5. 
          
              5. 残った母集団に対してサンプル数を算定する — 本ツールの④に対応します。
                6. 
          
              6. 発見した例外・誤謬を評価する — 本ツールの⑤に対応します。
                7. 
        
              
        
              
          全件分析を採用しても、この流れ自体は変わりません。
          変わるのは、④に到達する時点で母集団がどれだけ小さくなっているか、です。
